## 4. 협업 · 분업 방식



### 브랜치 = 분업 단위

폴더를 사람별로 나누지 않았습니다. 2인 규모에서 폴더 소유권을 고정하면 서로의 영역을 건드릴 때마다 대기가 생기기 때문에, **`feature/<slug>` 브랜치 하나 = 담당자 한 명**을 분업 단위로 삼았습니다. 같은 폴더라도 슬러그가 다르면 각자 진행합니다.

- `main`은 항상 플레이 가능한 상태 유지.
- 작업은 `feature/<slug>`에서 진행 후 main에 머지 (단기 feature, 1~3일 권장).
- 같은 `.tscn`을 두 사람이 동시에 수정하지 않음.



### 합의면 = 문서 + 칸반

- **현황:** `docs/spec/`  
- **이번 기능:** `docs/design/systems/<slug>.md` + Task  
- **진행 상태:** `docs/board/` 칸반 (Pages로 공유)

에이전트(`/feature`, `/push`)가 카드 열을 옮기고, **완료(**`done`**)는 사람이 플레이 확인 후에만** 처리합니다.  
→ AI·사람 협업의 운영 규칙은 제출물 4(AI 활용 기술 문서)에 상세히 기술합니다.

### 일상 리듬

1. 작업 전 `main` pull
2. feature에서 스펙·구현
3. `/push`로 머지 → 상대도 pull
4. `review` 카드를 서로 플레이해 피드백
