# Threat 엘리트 · 보스 진행 루프 — Codex 활용 기록

## Codex를 어디에 사용했나요?

Threat 상승을 엘리트·보스 마일스톤으로 확장하는 설계 문서, 칸반 카드, 엘리트 전투기 SVG 자산의 현재 변경 범위를 점검하고 제출용 기록을 정리하는 데 사용했다.

## 어떤 기능을 구현했나요?

Threat 상승 → 엘리트 전투 → 처치 후 적 증강 오퍼와 N번째 Threat의 보스 전투를 제안했다. 상태 전이, 일반 스폰 우선순위, 데이터 경계, 보상·UX·밸런스의 미결정 항목 및 검증 기준을 문서화했다. 구현 코드는 아직 추가하지 않았다.

## 어떤 문제를 해결했나요?

일반 Encounter와 엘리트·보스·증강 오퍼가 같은 시점에 겹쳐 시작할 수 있는 위험을 `boss > elite > augment offer > normal encounter` 우선순위와 별도 전투 상태 모델로 정리했다. 아직 확정되지 않은 수치와 실패 정책도 명시적으로 분리했다.

## 사람이 직접 결정한 부분은 무엇인가요?

확인 필요: 엘리트 빈도, 첫 등장 시점, 보스 주기와 보상, 전투 중 Threat 타이머·일반 스폰 정책의 최종 결정 주체와 확정값은 현재 대화 및 변경 내역만으로 확인할 수 없다.

## 활용 과정

1. 기존 Threat·Encounter·적 증강·보스 플래그 관련 현황 스펙을 확인했다.
2. 초안에 상태 모델, 충돌 우선순위, 데이터 경계와 검증 기준을 정리했다.
3. 구현 전에 결정해야 할 밸런스·실패 처리·접근성 항목을 `TBD`로 남겼다.
4. 현재 변경이 설계와 자산만 포함하며 Godot 실행 코드가 없음을 확인했다. 현황 스펙 해당 없음: 기존 `docs/spec`은 구현된 동작만 기술하고, 이 변경은 미확정 초안이다.
5. 자동 테스트·플레이테스트 결과는 확인 필요이며, 구현 단계에서 확정 정책에 맞춰 추가 검증한다.
