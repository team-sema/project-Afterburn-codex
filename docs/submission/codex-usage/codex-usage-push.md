# Push 시 Codex 활용 기록 — Codex 활용 기록

## Codex를 어디에 사용했나요?

Project Afterburn의 기능 완료 워크플로를 검토하고, Codex용·Cursor용 `/push` 스킬에 공모 제출 기록 절차를 설계·작성하는 데 사용했다.

## 어떤 기능을 구현했나요?

각 feature의 `/push` 직전에 `docs/submission/codex-usage/<slug>.md`를 생성하거나 갱신하고, 제출 질문 네 항목과 활용 과정을 같은 커밋에 포함하도록 하는 필수 게이트를 구현했다. 기록이 누락되거나 근거 없는 내용이 있으면 push를 중단한다.

## 어떤 문제를 해결했나요?

기능 개발이 끝난 뒤 Codex 활용 내역을 별도로 회상해야 해서 과정과 사람의 판단 근거가 누락될 수 있는 문제를 해결했다. 실제 대화·스펙·diff·테스트 결과를 feature 단위로 즉시 축적하도록 표준화했다.

## 사람이 직접 결정한 부분은 무엇인가요?

사람은 앞으로 작성하는 모든 아이템에 대해 Codex 사용처, 구현 기능, 해결 문제, 사람이 직접 결정한 부분을 제출용으로 기록하고, 활용 과정도 함께 설명하도록 요구했다. 또한 변경된 `/push` 스킬을 그대로 실행해 저장소에 반영하도록 최종 결정했다.

## 활용 과정

1. 사용자가 공모 제출 질문과 가산점 조건을 제시했다.
2. Codex가 기존 Afterburn·Cursor 스킬과 제출 문서 이력을 조사해 누락된 기록 단계를 확인했다.
3. 기능별 기록 경로와 다섯 개 필수 항목을 설계하고 두 `/push` 스킬에 동일하게 반영했다.
4. 사람이 직접 결정한 내용과 Codex 실행을 구분하고, 근거 없는 정보는 `확인 필요`로 남기는 안전장치를 추가했다.
5. 브랜치·스펙·Task·칸반·실제 활용 기록을 맞춘 뒤 diff 검증과 push 절차를 수행했다.
